Security & privacy posture

What this app does, and what it deliberately refuses to do.

CSP Locked-down content policy

A Content-Security-Policy meta tag denies everything by default — no iframes, objects, forms, base-URI tricks or third-party fonts. Only this document, data: images and the two AI endpoints are permitted. frame-ancestors cannot be set from a meta tag, so clickjacking defence belongs in response headers.

XSS No HTML injection path

Every user string is written with textContent via a DOM builder. There is no innerHTML, no eval, no new Function, no inline onclick= attributes and no template-string HTML anywhere in the app.

PP Prototype-pollution safe imports

Imported JSON is never merged. It is re-read field by field against a whitelist with type checks, length caps, numeric clamps and enum validation, so __proto__ or constructor keys cannot reach an object.

⌀ No third-party code

Zero scripts, zero CDNs, zero analytics, zero cookies. The app runs fully offline from a single file, so a supply-chain compromise has nothing to attach to.

⇄ Data minimisation

A plan is the only thing stored, in this browser's localStorage under one key. No guest names, no contact details and no payment data are ever requested — and nothing is uploaded.

✓ Output validation

Model output is parsed as JSON, shape-checked, length-capped and rendered as text. A malformed or hostile response cannot execute; it simply falls back to the built-in planner.

⏱ Cost & abuse throttling

AI calls are deliberately rate-limited client-side (15s between requests) and the button disables while in flight, so a stuck tab cannot spin up a spend loop.

⚑ Honest limits

Client-side code cannot keep a secret. A key entered here is visible to anyone with access to this browser session — use a scoped, low-limit key. In production, proxy the call through a server and drop 'unsafe-inline' for a nonce or hash.
